Acronym key (first use): MCP = Model Context Protocol (the tool protocol Cursor and other harnesses use to call Tell tools). LCP = Largest Contentful Paint (time to largest visible element). CLS = Cumulative Layout Shift (visual stability). INP = Interaction to Next Paint (tap/click responsiveness). GLSL = OpenGL Shading Language (shader code). WebGL = Web Graphics Library (browser 3D API). SFT/DPO = supervised fine-tuning / direct preference optimisation (training formats). GSAP = GreenSock Animation Platform (JS animation library). AVIF/WebP = image formats. Awwwards = juried web-design award site used as quality bar. Three.js = WebGL 3D engine. Zod = runtime schema validation library. Playwright = browser automation library used for capture.

0. Why this plan exists

ScrollTide sells 124 curated scroll-driven templates/prompts at $39/mo, $144/yr or $299 lifetime, with 10,000+ builders, 19 sections and 14 UI screens. Its strength is that each prompt encodes specific craft (parallax layers, named distances, typographic breaks) so AI output is specific rather than generic (a preview video before purchase is claimed but unverified from the homepage fetch). Its weakness is zero verification: the buyer trusts the preview and output quality depends on the buyer's own AI (Claude/Cursor/v0).

DesignProof's differentiator is not a bigger prompt library. It is that it generates the spec AND verifies the output in a disposable checkout, with independent detectors and a measured before/after. This plan lays out the engine capabilities that make that claim measurable against ScrollTide and the other nine rivals, in phased, falsifiable steps. No source changes here; everything below is a proposal to build.

Discrepancy to state plainly (user claim vs live site)

The user brief said ScrollTide has "600+ prompts, less than a coffee." The live site (fetched 2026-10-19) says 124 templates/prompts in the library and pricing of $39/mo, $144/yr, $299 lifetime — not "less than a coffee." Use 124 and the real prices in all copy and in the scorecard. Do not repeat 600+ as fact.

1.1 ScrollTide — https://scrolltide.co (main rival)

  • Best at: curated scroll-driven templates+prompts; prompt encodes specific craft (parallax layers, named distances, typographic breaks); 3D gated to Yearly/Lifetime; weekly new drops; "Prompt to Motion" ebook (separate product). Unverified from homepage fetch (deeper fetch needed before relying on): preview-video claim; "6 free heroes" claim and the SELENE detail (six parallax layers, trajectory inked to 384,400 km).
  • Offer structure: full landing pages (VALMORA, SELENE...), hero sections, single components (Particle Globe, Glow Ring Button, carousels, Image Tunnel 3D), GPU animated backgrounds (swirls/mesh/flows: MP4+still+component), page bands (pricing/testimonials/footers/bento/forms), UI screens (dashboards/wallets/consoles by category Finance/Commerce/Health...). Personal+client licence, no reselling templates, all sales final/no refunds, preview before buy.
  • Beat by: generate the spec (ConceptSpec + theme + motion review) AND verify the output (disposable proof, before/after measured deltas), instead of selling a static prompt the buyer runs through their own AI. DesignProof's swapTest (packages/design-skills/src/staged.ts) proves the concept changes with the brand; ScrollTide has no such test. ScrollTide is prompt+code library; DesignProof is spec+verification engine.
  • Measured: swap-test changedRatio >= 0.5 on 100% of generated specs; proof-verify pass/review/fail delta (before/after genericness delta reported (no baseline number claimed until Phase 0 measures one)); preview HTML passes checkPreviewBudgets (transfer <= 2048 KB, <=3 script tags, no http:// assets, viewport meta present); dossier plate 748/800 desktop, 798/844 mobile measured pass. Rival has no published budget numbers and no verification step.

1.4 60fps — https://60fps.design

  • Best at: motion micro-interaction granularity — names the exact interaction (e.g. "Uber Search Border Highlight", "CRED Swipe to Pay"), video-first; 2,110 shots, 494 apps, 93 app sites, 83 Motion, 20 Snippets, 67 Storyboards; taxonomy of gestures/patterns/effects/elements/categories; also MCP offering, mockups, glossary, jobs. 151.8K followers.
  • Beat by: name the interaction AND ship a runnable motion system. DesignProof's motionReviewFor (staged.ts) emits a one-sentence motion idea, tokens (duration 120–260 ms, easing cubic-bezier(0.22,1,0.36,1), stagger 60 ms) and a key interaction per siteKind, plus the 7 automatic motion checks in docs/15.
  • Measured: motion checks 1–7 pass on generated preview (transform/opacity only; reduced-motion replacement; @supports fallback; no long frames >50 ms; INP <=200 ms; lazy heavy bundles; durations from tokens); trace shows zero Layout/Paint during scroll. 60fps ships reference only, no generation/verification.

1.5 21st.dev — https://21st.dev

  • Best at: breadth via community — 12,000+ hand-crafted React+Tailwind components/templates/shadcn themes; live preview + full source + one-command shadcn CLI install; code lands in your repo, no lock-in; AI-ready prompt copy; MCP+CLI for agents (npx @21st-dev/cli init --client...); llms.txt, .md twins, OpenAPI.   • Beat by: breadth plus a unified design concept and verification that an installed component fits your page. DesignProof's taste/design-skills layer gives one coherent concept per site instead of many disconnected author takes; proof loop verifies fit.
  • Measured: installed-component fit checked by detectors on recapture (zero new genericness tells after install); concept present on every page of a multi-page scan (tell_capture_matrix routes). Rival has no fit verification; quality varies by author.

1.6 Aceternity UI — https://ui.aceternity.com

  • Best at: high visual impact per component; 200+ React/Tailwind/Motion components/blocks/templates (117+ free components, 182+ blocks, 17 templates, 3 landing pages); strong animated heroes, 3D card/marquee, shaders (4+ blocks), bento, MacBook scroll; agent install story ("tell your agent to build the website").

1.8 Three.js — https://threejs.org (r186)

1.9 Shadertoy — https://www.shadertoy.com

1.10 Lovable — https://lovable.dev

11.3 Gaps against the settled design rules

  1. Eight-stage approve-or-reject flow. The plan maps stages to tools well (Phase 7 addendum), but the flow exists only as primitives in this held branch (STAGED_STAGES, assertStageCanRun in staged.ts) — not on master, not exposed in Studio or MCP (Model Context Protocol). Gap: no phase requires a rejection test at the user interface level — "reject reruns only that stage, later stages untouched" needs a screenshot-verifiable Studio test, not only a unit test on the state machine. Add it to Phase 7 exit checks.
  2. Six named colour themes. Verified in code: ink-paper, forest-ledger, ember-clay, glacier-signal, nocturne-brass, plum-press. Gap: the plan never requires proving a theme change is only colour. Phase 1/4 mention "diff shows only hex values" for generated code, but the visual gate needs paired screenshots (same screen, two themes) showing identical layout, type, and spacing — otherwise themes become the colour-swap failure in new clothes.
  3. Swap test (proves the design changes with the brand). Verified: swapTest counts changed strings, pass at changedRatio >= 0.5. Flag: this is necessary but weak and gameable — a synonym rewrite passes with an identical page. Not yet measurable as a design claim. Strengthen before Phase 5 calls it proof: add (a) structural difference (section order / first-screen device must differ), (b) a screenshot difference measure on the first screen, and (c) a human blind check ("which brand is this for?" answered from the screenshot alone). Until then, write "string-level swap test" everywhere, not "proves originality".
  4. Crease golden bar / four-point visual gate. The plan uses dossier plate numbers well (748/800 desktop, 798/844 mobile) but never installs the four-point gate as a per-phase exit: (1) real proof at density in the first screen, (2) structure visible without scrolling, (3) hand-set type and spacing (not default scale/radius/shadow), (4) a designed mobile first screen at 390×844, not a squeezed desktop. Every phase that changes output (1–5 and the new specimen phase below) must exit on Playwright screenshots at 1280×800 and 390×844 judged against Crease on those four points. A phase that passes tests but fails the four points has not beaten anything.
  5. Template sameness — the failure Ashish rejected in pull requests #95–#102. This is the plan's biggest structural gap: specimen quality appears only inside exit checks. Template/specimen upgrade needs its own phase (insert after Phase 1, before motion/3D): rebuild one specimen (research dossier first, per the redesign calls) through the full staged flow, and prove — by the strengthened swap test plus the four-point gate — that changing the brand changes concept, first-screen device, and copy, not only colours. No new specimen work, and no "beats ScrollTide" claim, until that phase passes. ScrollTide's 124-template depth is beaten by verified distinctness, not by matching its count.

Flagged, not resolved here — I did not re-run the suite in this review.

11.7 Verdict

The plan's core claim is sound and, on my own fetches, true: ScrollTide sells a static prompt with zero verification at $39/$144/$299 for 124 templates, and a staged, concept-first, swap-tested engine with measured proof is a genuinely different and stronger offer. The plan is not yet shippable as written until: (a) the unproven rival details in §11.2 are fetched or labelled, (b) the test baseline is reconciled per head (474 vs 430), (c) the swap test is strengthened beyond string counting, (d) the four-point Crease gate becomes a per-phase screenshot exit, (e) specimen upgrade gets its own phase, and (f) Phase 7 states the 19-by-replacement count up front, with prompt-plus-source export marked undecided for Ashish. With those folds, I endorse it as the plan of record.
